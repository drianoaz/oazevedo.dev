# ADR-007: Animation Design — Phased, Mood-Mapped Clip Catalog with Transitions

## Status

Accepted

## Date

2026-06-13

## Context

ADR-003 puts the mood/energy state in an external store that selects a target
animation; ADR-005 delivers baked clips crossfaded by mood with procedural gaze
on top; ADR-006 builds the rig those clips animate. What remains is the
**animation design**: which clips exist, how they map to mood/energy, and how
transitions between them feel continuous rather than snapping. This must serve a
living-pet read (ADR-001) while staying within the Phase-1 scope and performance
budget.

## Decision

Author a **phased, mood-mapped clip catalog with dedicated transition clips**:

- **Phase-1 catalog** — `idle`, `sleep`, `stretch`, `glance`, `walk`. Each mood
  has a **primary loop clip** (e.g. `sleepy → sleep`, `curious → glance/idle`,
  `bored → idle`, `playful → walk/stretch`).
- **Transitions** — author **entry/exit transition clips** for the conspicuous
  pose changes (e.g. `sit → sleep`, `sleep → stretch`) so the store can route
  through a transition rather than crossfading directly between incompatible
  poses. Smaller/compatible changes use a plain temporal crossfade.
- **Loop seams** — author loops with stitchable start/end poses so repeated
  playback reads as continuous.
- **Selection** — the store emits a target intent; the renderer plays the
  transition (if defined for the current→target pair) then the target loop,
  crossfading via drei `useAnimations`. Procedural gaze (head/neck) layers on
  top of whatever clip plays (ADR-005).
- **Phasing** — later phases extend the catalog without changing the mechanism:
  Phase 2 adds `scratch`, `bellyUp`, `perk`; Phase 3 adds `fetch`, `pounce`,
  `chase` and per-toy behaviors (ADR-002).

The clip names are the typed `ELIS_CLIPS` contract with the export (ADR-005/006).

## Alternatives Considered

### Alternative 1: One clip per mood, direct crossfade only

- **Description**: A single loop per mood/action, always swapped by a simple
  temporal crossfade; no dedicated transition clips.
- **Pros**: Least animation work; fewer bytes.
- **Cons**: Conspicuous pose changes (lying → walking) look unnatural when
  blended directly; weakens the "alive" read.
- **Why rejected**: Transitions are where the living-pet illusion holds or
  breaks; a few transition clips are worth the cost.

### Alternative 2: Rich library from the start

- **Description**: Author a broad catalog up front — many idle variations,
  micro-moments, fillers — for maximum variety.
- **Pros**: Most lifelike, least repetitive.
- **Cons**: Heavy up-front animation effort; risk to Phase-1 scope and the byte
  budget.
- **Why rejected**: Variety is a Phase-3 enrichment goal; Phase 1 ships a tight
  set and grows via the same mechanism.

## Consequences

### Positive

- Believable transitions for the poses that matter, at controlled cost.
- The selection mechanism is fixed once; later phases only add clips.
- Clean separation: baked clips for body motion, procedural layer for gaze.

### Negative

- More clips than a one-per-mood approach (transitions add authoring work).
- The store must track current→target pairs to choose the right transition.

### Risks

- **Transition combinatorial growth** — mitigated by authoring transitions only
  for conspicuous pose pairs, not all pairs.
- **Clip-name drift** — mitigated by the single typed `ELIS_CLIPS` map shared
  with the Blender export (ADR-005/006).

## Implementation Notes

The mood→clip map and transition table live alongside `ELIS_CLIPS` in
`src/components/elis/`. Energy thresholds in the ADR-003 store decide when
`sleepy` escalates to `sleep` (→ `activity: 'rest'`, pausing the loop per
ADR-004).
